# 웹소설 스튜디오 개발 생애주기와 개발 단계

- 작성일: 2026-11-06
- 근거: `webnovel_studio_integrated_plan.md`(11장 로드맵), `docs/PLATFORM_GAP_ANALYSIS.md`
- 원칙: 원고 안전과 AI 신뢰성이 기능 확장보다 먼저다. MVP 검증 전에는 SaaS, 등급제, 자동 점수에 투자하지 않는다.

---

## 1. 개발 생애주기 (공통 흐름)

모든 단계가 같은 순서를 따른다. 단계마다 산출물과 종료 기준(게이트)이 있고, 게이트를 통과해야 다음으로 넘어간다.

| 순서 | 활동 | 산출물 | 담당 |
|---|---|---|---|
| 1 | 결정 | 열린 결정(D-1~D-10) 확정 기록 | 작가, 기획자 |
| 2 | 명세 | 기능 ID별 인수 조건, 데이터 모델 | 기획자 |
| 3 | 설계 | 모듈 경계, API 계약, 저장 구조 | 개발 |
| 4 | 구현 | 코드, 마이그레이션 | 개발 |
| 5 | 검증 | 테스트 결과, 보안 점검, 인수 조건 체크 | 개발, 작가 |
| 6 | 파일럿 | 사용 기록, 막힌 지점 3개 | 파일럿 작가 |
| 7 | 회고·반영 | 다음 단계 범위 조정 | 전원 |

### 1-1. 품질 게이트 (모든 단계 공통)

- `tsc --noEmit`과 `vite build`가 통과한다.
- 해당 단계의 기능 ID 인수 조건을 항목별로 확인한 기록이 있다.
- 원고 유실, AI 실패 은폐, 토큰 노출이 0건이다.
- 새 의존성은 라이선스와 취약점을 확인한다. 외부 입력을 받는 코드는 검증 함수를 거친다.
- 수치(화 수, 분량 기준 등)는 단일 기준 파일에서만 정의한다.

### 1-2. 브랜치와 릴리스

| 항목 | 규칙 |
|---|---|
| 브랜치 | `main` 보호, 작업은 `feat/<기능ID>-<요약>` |
| 커밋 | `feat/fix/chore(기능ID): 요약` |
| 릴리스 | 단계 종료 시 태그 `phase-N` |
| 롤백 | 태그 단위로 복귀. 데이터 구조 변경은 마이그레이션과 백업을 함께 둔다 |

## 2. 개발 단계 (Phase 0~4)

### Phase 0. 결정 (1~2주) 상태: 진행 전

**목표:** 코드가 기대는 기준 수치와 구조를 확정한다.

| 작업 | 산출물 |
|---|---|
| D-1 1막 종료 화, D-2 단위 체계, D-3 화 분량 기준, D-4 막 구조 확정 | 결정 기록 |
| D-5 제작 절차, D-6 복선 경고 기준, D-7 장르 규칙 확정 | 결정 기록 |
| D-8 점수 체계 제외, D-9 내보내기 형식, D-10 기본 모델은 보류 가능 | 보류 사유 |
| 단일 기준 파일 `src/config/storyRules.ts` 설계 | 설계 문서 |
| 데이터 모델 확정 (작품→막→아크→챕터→화→씬→비트) | 모델 정의 |

**종료 기준:** D-1~D-4가 확정되고 단일 기준 파일 초안이 승인된다.
**선행 관계:** Phase 2의 U-01, U-02는 D-2, D-3 확정이 필요하다.

---

### Phase 1. 원고 안전 MVP (4~6주) 상태: 구현 완료, 브라우저 실사용 검증 전

**목표:** 작가가 한 회차를 쓰고, AI 제안을 적용하고, 다시 열어도 남고, 파일로 복원할 수 있다.

| 하위 단계 | 기능 ID | 상태 |
|---|---|---|
| 1-A 보안 | X-01~X-03 | 완료 |
| 1-A 보안 | X-04 원고·소스 분리 | 부분 완료 (원고 저장소 미구현) |
| 1-B AI 신뢰성 | A-01~A-05, A-08 | 완료 |
| 1-C 원고 보존 | S-01~S-03 | 완료 |
| 1-D 복원 | S-05 마크다운 묶음 내보내기·가져오기 | 완료 (zip, 단위 테스트 통과) |
| 1-D 복원 | S-04 씬 단위 버전 이력·복원 | 완료 (씬당 최대 20개) |
| 1-D 복원 | S-06 손상 데이터 격리 | 완료 (프로젝트 데이터 한정) |
| 1-E 기반 | 자동화 테스트 도입 (`npm test`, 36개) | 완료 (UI 테스트는 없음) |

**남은 작업 상세**
1. 저장 계층을 `Storage` 인터페이스 뒤로 분리한다. 현재 구현은 `localStorage`.
2. 마크다운 묶음 규칙(폴더, 파일명, 메타데이터)을 정하고 내보내기와 가져오기를 구현한다.
3. 씬 저장 시 이전 본문을 이력으로 남기고, 복원도 이력으로 기록한다.
4. 파싱 실패 데이터는 삭제하지 않고 격리 영역으로 옮기고 화면에 알린다.
5. 단위 테스트: `validateBranch`, `parseGithubRepo`, `sanitizeCommitMessage`, `handleApplyAiTextToScene`, `callModel` 오류 분기.

**종료 기준 (MVP 성공 기준)**
- [ ] AI 적용 후 새로고침해도 원고가 유지된다 (S-01) — 구현됨, 파일럿 확인 필요
- [x] AI 실패가 실패로 표시된다 (A-01)
- [ ] 같은 작품 안에서 분량·진행률 숫자가 모든 화면에서 같다 (Phase 2에서 완료)
- [ ] 백업 파일로 다른 기기에 복원할 수 있다 (S-05) — 구현·왕복 테스트 통과, 실제 두 기기 검증 필요
- [ ] 설정 변경 시 영향 목록이 뜬다 (Phase 2에서 완료)
- [x] 보안 점검에서 명령 주입, 토큰 노출 항목이 0건이다

### Phase 2. 설정·복선·윤문 (4~6주) 상태: 대부분 구현, 미완료 항목 있음 (2026-11-06 기준)

**목표:** 파일럿 작가 3명이 한 챕터를 마감한다.

| 하위 단계 | 기능 ID | 내용 |
|---|---|---|
| 2-A 구조 | U-01, U-02, U-03 | 단위 계층 강제, 분량을 씬 합계로 계산, 5,000자 미만 미달·9,000자 초과 표시. 수동 입력 모달 제거 |
| 2-A 구조 | U-04, U-05 | 엔딩 훅 기록, 화 편성과 즉시 재계산 |
| 2-B 설정 | C-01, C-02, C-03 | 설정결정 목록, 영향 범위 조회, 고증 목록 |
| 2-C 복선 | C-04, C-05, C-06 | 복선 상태 흐름, 회수 예정 초과 경고, 미결 목록 |
| 2-D 윤문 | R-01, R-02 | `%%` 주석 편집, 윤문 비교노트와 판정표 |
| 2-D 윤문 | R-03, R-04 | 6유형 문체 점검, 화 단위 반복 점검 |
| 2-E 게이트 | 6-1 단계 게이트 | 챕터 확정 조건(복선 회수 확인, 미결 0건 또는 보류) |

**선행:** Phase 0의 D-1~D-4, D-6.
**종료 기준:** 파일럿 작가 3명이 한 챕터를 확정한다. 설정 변경 시 영향 목록이 뜬다. 숫자 불일치가 0건이다.

### Phase 3. 재구성·현황·모델 비교 (4주) 상태: 3-B 현황판 구현, 나머지 미착수

**목표:** 설정 변경을 아직 쓰지 않은 부분에 반영하고, 진행을 계산값으로 보여 주며, 모델을 비교한다.

| 하위 단계 | 기능 ID | 내용 |
|---|---|---|
| 3-A 재구성 | U-06 | 씬→챕터→아크→막 완료 시 재구성 범위 제안. 작가 승인 후 실행 |
| 3-B 현황 | D-01, D-02, D-03 | 지표 카드(계산값), 근거 출처 연결, 미공개 항목 가림 |
| 3-C 모델 | M-01, M-02, M-03 | 같은 씬 다중 모델 생성, 기준 점검, 씬 종류별 기본 모델 |
| 3-D 운영 | A-09 | 작품 단위 호출 횟수와 추정 비용 표시 |
| 3-E 분석 | R-05 | 대사 비중, 문장 길이 분포 |

**종료 기준:** 재구성 제안 채택률을 측정할 수 있다. 모든 현황 숫자에 근거가 연결된다.

### Phase 4. 확장 (이후) 상태: 미착수

**진입 조건:** 파일럿 전환율 기준 충족. 가격은 파일럿 결과로 확정한다.

| 연동 | 옵시디언 연동, DB 기반 저장으로 전환 검토 |
| 사업 | 결제, 구독 또는 작품당 과금 |
| 인물 | C-07 인물 시간선 자동 검사 |
